# mydt-pipeline

Automated update, validation, consolidation and reporting for SDG 4 education survey templates.

Countries report education data in Excel templates with built-in checks. Each survey cycle, someone has to roll those templates forward a year, pre-fill them, translate them, then read back hundreds of returned workbooks, check them, combine them into one database and send each country a review of its indicators. This repository automates that cycle end to end.

> **Demonstration build.** The templates here are modelled on the publicly described structure of multi-year dynamic templates (MYDTs). They are not the UIS's own templates. All countries (codes XAA–XAJ, reserved for user assignment in ISO 3166) and all figures are fictional and generated by `mydt/synth.py`.

## What it does

```
 country templates (.xlsx, 5 languages)       national yearbooks (mined, .csv)
              │                                           │
        reader.py  ── every value keeps its cell address ─┤
              │                                           │
       validate.py  ── 16 rules, thresholds in config/rules.yaml
              │                                           │
     consolidate.py ── one tidy database: CSV, SQLite, Stata .dta
              │
     indicators.py  ── GER, NERT, out-of-school rate, GPI, repeaters,
              │        pupil-teacher ratio, trained teachers, expenditure
       report.py    ── QC checklist (.xlsx) and indicator review (.html) per country
              │
       update.py    ── next cycle: add the new year, pre-fill, translate, test
```

| Step | Command | Output |
|---|---|---|
| Make sample data | `python -m mydt generate` | 8 country templates with 11 planted errors, 2 mined sources, reference population, previous release, answer key |
| Process a cycle | `python -m mydt run` | `output/consolidated/`, `output/qc/`, `output/reports/index.html` |
| Prepare next cycle | `python -m mydt build-templates --survey-year 2027` | Pre-filled templates in EN, FR, ES, PT, RU, each functionally tested |
| Test a template | `python -m mydt test-template <file.xlsx>` | Structure, formulas, validation, protection; formula results recalculated in LibreOffice and compared with Python |
| Point-and-click | `streamlit run app/streamlit_app.py` | Upload templates, see flags and indicators, download everything |
| Cross-check in R | `Rscript r/validate_mydt.R` | Independent R implementation of the core checks; confirms R and Python flag the same cells |

## Quick start

```bash
python -m venv .venv && source .venv/bin/activate
pip install -e ".[dev]"
python -m mydt generate
python -m mydt run
open output/reports/index.html
pytest -q
```

## Design choices

**One layout spec.** `mydt/spec.py` is the only place that knows where a number lives in the workbook. The writer, the reader and the functional tests all use it. When the template changes (a new year, a new row), you change the spec, not three scripts.

**Language-neutral codes, translated labels.** Sheet names and row and column codes (`ENRL_AGE`, `L1`, `G7`, `F`) never change. Only the visible labels come from `config/labels.yaml`. One reader therefore parses every language version, and a test checks that every language has every label.

**The reader does not trust column positions.** It reads year and sex headers from the sheet itself, so a template with a different set of years still parses.

**Every flag points to a cell.** Values keep their address (`ENRL_GRADE!N12`). A country gets "cell N12 on ENRL_GRADE", not "something is wrong with lower secondary".

**The workbook checks itself, and the Python checks agree.** The CHECKS sheet holds live Excel formulas so countries see problems before they submit. `test-template` recalculates the workbook in LibreOffice and confirms the formulas give the same totals as the Python pipeline.

**Thresholds are configuration.** Tolerances and plausible ranges live in `config/rules.yaml`.

**Tested against known answers.** The generator plants errors and writes an answer key. The tests require every planted error to be caught and every flag raised to be explained by the key, so the suite fails on missed errors and on false alarms.

## Validation rules

| Rule | Check | Severity |
|---|---|---|
| R00 | Cover page and all sheets present, survey year correct | Error |
| R01 | Only numbers or the codes m, a, x, n in data cells | Error |
| R02 | No negative values | Error |
| R03 | No blank cells (a missing value must be coded) | Warning |
| R04 | Female + Male = Total | Error |
| R05 | Age table and grade table give the same totals | Error |
| R06 | Age cohorts move consistently (age *a* in year *t* → age *a+1* in *t+1*) | Warning |
| R07 | Enrolment at each age does not exceed population | Warning |
| R08 | No year-on-year change in enrolment above 20% | Warning |
| R09 | Repeaters do not exceed enrolment | Error |
| R10 | Expenditure by level ≤ total education ≤ total government ≤ GDP | Error |
| R11 | Data source given for every table with data | Warning |
| R12 | Trained teachers do not exceed total teachers | Error |
| R13 | Pre-filled population not modified by the country | Warning |
| R14 | Indicators within plausible ranges | Warning |
| R15 | Revisions to previously published indicators larger than 3 points | Info |

## Indicators

Population denominators come from the reference population file (UN estimates in real use), not from the copy displayed in the template.

| Code | Indicator |
|---|---|
| `GER_L1..L3` | Gross enrolment ratio by level |
| `GPI_GER_L1..L3` | Gender parity index of the GER |
| `NERT_L1, NERT_L2` | Total net enrolment rate |
| `OOSR_L1, OOSR_L2` | Out-of-school rate (SDG 4.1.4) |
| `REPP_L1..L3` | Percentage of repeaters |
| `PTR_L1..L3` | Pupil-teacher ratio |
| `TRTP_L1..L3` | Proportion of teachers with the minimum required training (SDG 4.c.1) |
| `XGDP` | Government expenditure on education as % of GDP |
| `XGOVEXP` | Government expenditure on education as % of total government expenditure |

## Repository layout

```
mydt/            spec, template writer, reader, validation, indicators, consolidation, reports, updater, CLI
config/          rules.yaml (thresholds), labels.yaml (EN/FR/ES/PT/RU labels)
app/             Streamlit front end
r/               independent R cross-check
tests/           pytest suite
data/            generated sample inputs (submissions, mined, reference)
```

## Limits

- The translations were produced with AI help and need a native speaker's review before going to countries.
- Real UIS templates have more tables (tertiary, pre-primary, finance by nature of spending) and more indicators. The spec is built so that adding them means adding sheet definitions, not rewriting the reader.
- Stata output is the `.dta` export. The processing scripts themselves are Python and R.
